# Anti-AI audit

Audit applied to the recommended Signal Ledger prototype.

| Check | Result | Resolution |
|---|---|---|
| Four KPI cards across top | Removed | Daily facts are a single inline ledger header. |
| Excessive rounded containers | Removed | Main structure uses rules and aligned regions; only controls have a small radius. |
| Generic buttons | Removed | Actions use compact text/ink controls tied to specific records. |
| Generic dashboard chart | Removed | No decorative chart; time and daily counts are part of the signal chronology. |
| Generic SaaS navigation | Removed | Flat typographic rail/top bar expresses Signals, Radars, and Leads. |
| Empty space without hierarchy | Removed | Space separates time groups and dossier sections rather than floating cards. |
| Repeated card layouts | Removed | Signals are rows, Radars are definitions, and company detail is a dossier. |
| Status-pill overuse | Removed | Lead state is usually text with a small edge marker; one select remains for mutation. |
| Icon clutter | Removed | No decorative icon set; text and a minimal geometric signal mark carry navigation. |
| Templated admin-panel composition | Removed | No sidebar-plus-bento-dashboard or dashboard card grid. |
| Blue-primary defaults | Removed | Ink/navy actions and amber match evidence replace generic blue CTAs. |
| Could belong to any CRM | Pass | GEMI identifiers, incorporation events, KAD criteria, Radar provenance, and the event→lead chain define every screen. |

Residual watch item: the compact navigation rail is a familiar pattern in isolation. It remains acceptable because it is typographic, non-decorative, and the first working surface is an unmistakable registration ledger rather than generic admin chrome.
